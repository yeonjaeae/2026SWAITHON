# RE : GREEN · API 연결 전 프론트엔드 양식

HTML 4개와 페이지별 JavaScript로 구성한 정적 프론트엔드입니다.
서버 주소 입력, API 요청, 자동 추천, 환경 효과 계산, AI 이미지 생성은 포함하지 않습니다.

## 실행

ZIP을 새 폴더에 전부 압축 해제한 뒤, VS Code에서 폴더를 열어 `index.html`을 Live Server로 실행하세요.
또는 폴더에서 `python -m http.server 5500`을 실행하고 `http://localhost:5500`을 여세요.
이 서버는 HTML을 여는 정적 서버이며 별도 백엔드가 필요하지 않습니다.
같은 주소의 같은 탭에서 열어야 페이지 간 저장이 일관되게 동작합니다.

## 화면 사용 순서

1. 공간 탐색: 서울 지도에서 네모 범위를 드래그 → 대상 이름 입력 → 설계하기.
2. 공존 설계: `녹화 영역 그리기` 선택 → 지도에서 사각형 드래그. 여러 개 그릴 수 있습니다.
3. 보존할 곳은 `보존 영역 그리기`로 표시합니다. 녹화와 겹치면 보존이 우선입니다.
4. 영역별 삭제, 되돌리기, 전체 지우기를 사용할 수 있습니다. 드래그 중 Esc는 그리기 취소입니다.
5. 식생과 공존 조건, 메모를 입력하고 결과 → 리포트로 이동합니다.
6. 리포트에서 입력 내용을 JSON으로 다운로드하거나 브라우저 인쇄창에서 PDF로 저장합니다.

현장·항공사진을 직접 올리면 지도 배경 대신 사용할 수 있습니다. 배경 변경 시 기존 사각형은 초기화됩니다.
사진은 브라우저 내부에서 최대 1400px JPEG로 축소되며 화면에 맞추어 일부 잘릴 수 있습니다. 서버에는 전송하지 않습니다.

## 비율과 사각형

녹화 비율 슬라이더나 자동 세로 띠 색칠은 없습니다. 사용자가 그린 사각형만 표시합니다.
녹화 비율 = (녹화 사각형 합집합에서 보존 영역을 제외한 넓이) / 설계 화면 넓이.
겹친 녹화 사각형은 중복 계산하지 않습니다. 보존 영역은 우선 표시됩니다.
비율은 1000×700 화면 좌표 기준이며 실제 토지 면적·GIS 분석 결과가 아닙니다.
JSON에도 좌표계와 화면 크기를 명시합니다. 사용자 사진 자체는 JSON에 포함하지 않습니다.

## 파일별 역할

| 파일 | 역할 |
|---|---|
| index.html / js/index.js | 서울 지도 선택, 추천 목록의 빈 양식 |
| design.html / js/design.js | 사각형 녹화·보존 영역 편집, 식생·조건·메모 입력 |
| result.html / js/result.js | 원본 배경과 직접 표시한 영역 비교 |
| report.html / js/report.js | 설계 요약, JSON 및 인쇄/PDF 저장 |
| js/common.js | 세션 상태 저장, SVG 지도, 드래그, 사각형 합집합 계산 |
| css/common.css | 공통 디자인, 모바일, 인쇄 스타일 |
| assets/image-02.webp | 기존 파일의 저장된 서울 지도 이미지 |

각 페이지는 자기 화면의 HTML만 사용합니다. 다른 페이지를 숨겨서 불러오는 구조와 공통 엔진 의존성을 제거했습니다.

## 연결 전 표시

- 녹지 부족 히트맵: 연결 전 비활성화.
- 추천 후보지: 빈 목록 안내. 가상 후보지를 자동 생성하지 않습니다.
- 설계 전후: 사용자가 그린 계획 영역 비교이며 AI 생성 사진이 아닙니다.
- 녹지 면적, 수목 수, 탄소흡수량, 비용: 값 없이 `—` 표시.
- 지도는 저장된 이미지이며 외부 지도 타일이나 API를 요청하지 않습니다.
- 설정은 sessionStorage에 저장되어 같은 탭의 새로고침·페이지 이동에서 유지됩니다. 탭을 닫으면 삭제됩니다.

## 확인 범위

JavaScript 문법, HTML 구조, 페이지별 DOM 참조, 로컬 파일 링크를 검사했습니다.
역방향 드래그 좌표, 겹치는 녹화 영역의 합집합, 보존 우선 처리, 비율 계산을 자동 검사했습니다.
현재 실행 환경의 브라우저 제한으로 실제 클릭·터치와 인쇄 화면은 검증하지 못했습니다.
